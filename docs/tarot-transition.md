# 혈액형 → 타로 전환

기존 변경사항의 배포 기준 커밋은 앱 `0a350bd`, 서버 `affbdd4`이며, 두 저장소의 origin/dev와 origin/master에 푸시했다. 이 문서의 타로 변경사항은 그 이후 작업이다.

## 동작

- 사주 · 점성술 · MBTI · 타로 네 관점. 메이저 아르카나 22장, 정방향만 사용한다.
- 한국 시간 하루 한 장. 사용자 식별자와 날짜로 정하고 서버 운세에 저장한다. 생년월일·MBTI·닉네임 수정으로 다시 뽑히지 않는다.
- 홈 마스코트를 꾹 누르면 오늘의 운세와 타로를 함께 공개한다. 타로 화면에서는 타로만 공개하며 운세 뽑기나 AI 풀이 요청을 실행하지 않는다. 타로 공개 기록은 기기·사용자·날짜별로 따로 저장한다. 콘텐츠 탭과 이전 혈액형 상세 링크도 같은 카드로 연결된다.
- 타로는 해볼 행동과 질문을 전하고, 새 일일 운세의 분야별 점수에도 카드별로 작은 보정을 더한다. 타고난 성격을 판정하지 않는다.
- 궁합은 사주 · 태국 점성술 · MBTI · 관계 타로를 보여준다. MBTI를 모르면 그 자리에는 띠 풀이가 온다. 관계 카드는 오늘의 카드와 별개이며 결과에 보관한다.
- 테마 운세는 해당 주제의 조언 카드를 함께 보관한다. 평생 성향 비교에서는 사주 · 점성술 · MBTI만 사용한다.
- 카드 그림은 실제 라이더–웨이트–스미스 카드의 상징과 구도를 참고해 별도로 생성한 회화 이미지 22장과 뒷면이다. 1024×1536 PNG 원본은 assets/tarot/source, 앱용 WebP는 assets/tarot에 있다. 카드 위 마스코트 오버레이는 제거했다. 추가 패키지는 없다.

## 기존 데이터

기존 종합 점수·풀이·혈액형 분석과 구매한 풀이를 일괄 재생성하지 않는다. 기존 일일 운세에는 카드만 추가 저장하며, 종합 풀이 화면에 기존 관점으로 보관된 이야기임을 표시한다. 새 운세에도 `blood` 응답을 남겨 기존 앱이 필드를 읽을 수 있게 하고, 새 화면과 종합 풀이에는 `tarot`를 사용한다. 혈액형을 수집하지 않은 새 프로필은 null이다. 기존 프로필 값은 새 폼이 항목을 생략해도 보존한다.

새 앱은 혈액형 입력·전송을 하지 않으며, 새 궁합 초대에는 혈액형을 공유하지 않는다. 기존 궁합 기록에 남은 데이터와 기존 앱의 기능을 위한 레거시 타입·자산은 유지한다.

## 출시 순서

1. 서버의 nullable 프로필 컬럼과 API를 먼저 반영한다. SQL은 서버 저장소의 `scripts/sql/20261031-tarot-profile.sql`에 있다. 현재 dev/prod 설정의 schema sync도 같은 변경을 적용한다.
2. 신규·기존·게스트 전환 프로필과 기존 구매 기록을 데브에서 확인한다. 특히 새 null 프로필을 이전 앱에서 여는 경우는 기기 검증이 필요하다.
3. 웹과 앱을 갱신한다. 앱 배포 전 fingerprint를 확인한다. 이번 작업에는 app.json의 소개 문구 변경도 포함되어 있다.
4. production OTA는 별도 명시적인 요청이 있을 때만 진행한다.

## 검증

서버 엔진·API 테스트는 카드 안정성, 카드별 점수 반영, 혈액형 없는 가입, 기존 프로필 보존, 기존 운세 보존을 포함한다. 브라우저 검증은 실제 엔진이 생성한 로컬 테스트 응답을 사용하며, 실제 서버 계정을 만들지 않는다. 실기기 테스트와 실제 서버를 연결한 통합 검증은 별도다.

검증 완료: 앱 lint(오류 0, 경고 129), 앱·서버 타입 검사, 서버 빌드, 관련 서버 테스트와 추가 회귀 테스트, iOS·Android·웹 export. 브라우저에서는 카드 공개·새로고침 유지·공유·혈액형 없는 프로필 저장 요청·320px 다크 모드·기존 혈액형 가이드 링크·KST 자정 전환을 확인했다.

## 점수 반영

`rule-v6-tarot`부터 22장에 연애·재물·직장·관계별 -4~+4의 신호를 정의한다. 점성술·MBTI와 같은 0.35 가중치로 합산 후 기존 점수 보정식을 거친다. 종합 점수와 기간 운세에도 반영되며, 실제 점수 차이는 사주 흐름과 반올림에 따라 달라진다. 카드는 계정·날짜로 미리 정해지고 공개 시 재계산하지 않는다. 궁합 점수는 이번 변경 대상이 아니다.

새 일일 운세에는 `combined.viewpointImpacts`를 저장한다. 각 값은 최종 분야 점수에서 해당 관점을 제외한 동일 계산의 점수를 뺀 값이며 합산 수치가 아니다. 분야 상세는 사주·점성술·MBTI·타로만 표시한다. 이전 운세의 점수는 보존하고, 영향 수치가 없는 기록에는 기존 분석 신호임을 명시한다.

## 혈액형 개입 경로 전수 점검 (2026-10-31)

앱·백엔드의 코드, AI 입력과 지시문, 규칙 문장, API 스키마, 문서를 검색하고 실제 호출 경로를 확인했다.

수정한 경로:
- 타로가 없는 입력을 조합할 때 혈액형 태그·문장으로 돌아가던 처리를 제거하고 오늘의 타로를 생성한다.
- 혈액형만 바뀌어도 운세 프로필 버전이 올라가거나 궁합 상대가 별도 기록으로 분리되던 비교를 제거했다.
- 유료 풀이의 재사용 식별값에서 본인·상대의 혈액형을 제외했다. 기존 혈액형 포함 식별값은 같은 기록으로 재연결한다. 이전 스냅샷의 혈액형은 이 전환을 위한 비교에만 남기고 AI 근거로 보내지 않는다.
- 상대 혈액형을 모를 때 O형으로 가정하던 값을 제거했다.
- 규칙 문장 초안과 스토어 소개의 현행 관점 설명을 타로로 바꿨다. 사용하지 않는 평생운·연간운·궁합 혈액형 상수도 제거했다.
- 일일 AI 지시문에도 혈액형을 새 풀이의 근거로 쓰지 않도록 명시했다.

의도적으로 남긴 호환 요소:
- 기존 DB 프로필·구매 기록·과거 운세, API의 nullable/deprecated 혈액형 필드.
- 구버전 앱을 위한 `analyses.blood` 전용 생성기. 새 앱의 점수·키워드·종합 풀이·AI 입력은 이 결과를 소비하지 않는다.
- 이전 문장 DB의 `{blood}`를 읽기 위한 검증기와 이전 기록의 타입·아이콘·색 이름. 현행 문장 생성에는 사용하지 않는다.
- 이전 `/analysis/blood`, `/g/blood` 링크는 타로 화면으로 연결한다.
- 기존 혈액형 보관 사실을 알리는 개인정보처리방침과 당시 스토어 제출 이력.

A/B/O/AB/null 간에 일일 결과·영향 수치·주간 결과·상세 사주·평생운·연간운·월간운·세 가지 테마·궁합·심층 궁합·상담 계산 근거가 같은지 회귀 테스트로 검증한다. 과거에 저장된 풀이 문구를 소급해서 다시 쓰지는 않는다. 검증은 로컬 코드와 테스트 기준이며 운영 DB나 배포 상태를 변경하지 않았다.
